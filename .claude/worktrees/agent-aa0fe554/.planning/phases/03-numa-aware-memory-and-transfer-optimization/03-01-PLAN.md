**MEM-01: NUMA-local downgrade preference (single-GPU, enabled in CI)**

TEST_CASE "numa_local_downgrade_prefers_local_host" tagged [downgrade][mem_01]:
- Create a memory manager with 2 HOST spaces using reservation_manager_configurator:
  - builder.set_number_of_gpus(1), set_per_host_capacity(4GB), set_number_of_host_spaces(2) (or use_host_per_gpu with 2 host spaces).
  - Check what the configurator API actually supports. If set_number_of_host_spaces does not exist, manually build space_configs with 2 HOST spaces (device_id 0 and 1) using the same pattern as the existing make_test_memory_manager but adding a second host space.

- Create a GPU batch, lock it for in-transit.
- Execute downgrade_task::execute(stream).
- After execution, verify the batch landed on HOST tier.
- Verify the batch's memory_space device_id == 0 (the preferred NUMA node).
- This proves downgrade_task passes the NUMA preference through to any_memory_space_in_tier_with_preference and that stable_partition puts the preferred space first.

**MEM-02: Cross-NUMA fallback (single-GPU, enabled in CI)**

TEST_CASE "numa_downgrade_falls_back_to_cross_numa" tagged [downgrade][mem_02]:
- Create a memory manager with 2 HOST spaces (device_id 0 capacity = small e.g. 1KB so it cannot fit a batch, device_id 1 capacity = 4GB).
  - This requires manually constructing space_configs. Look at reservation_manager_configurator::build() output format and replicate it, but set HOST space 0 to a tiny capacity (smaller than one batch).
  - If the configurator does not allow asymmetric host capacities, construct the memory_space_config vector manually with: 1 GPU space + 2 HOST spaces (space 0: 1KB limit, space 1: 4GB limit).
- Create downgrade_task_global_state with numa_preferred_device_id = 0 (prefers the small space).
- Create a GPU batch (~4KB of INT32 data), lock for in-transit.
- Execute downgrade_task::execute(stream).
- Verify batch is on HOST tier.
- Verify batch's memory_space device_id == 1 (fell back to the cross-NUMA space because space 0 was too small).
- This proves the stable_partition fallback: preferred space tried first, failed, then next candidate succeeded.
